# 个人单账号使用与接口说明

本次修改面向一个 owner、一个服务实例。邮件数据、审批、完整对话和任务状态各自保存；检索版本、模型调用预算、证据和执行权限使用独立模块。后台线程上限不代表支持多个 API worker。

当前新增任务记忆、历史命中窗口、语义摘要试验、工具结果分页与 checkpoint v2，参见 [上下文优化说明](context-development-2026-09-10.md)。删除会话现可使运行中的旧任务失效，未清理完成的派生数据通过 `cleanup_pending` 报告。

## 页面日常流程

1. 按部署指南准备依赖、模型和语料。在侧栏查看索引状态，必要时明确预热。存活提示不证明模型可用；旧索引不兼容时先备份再重建。
2. 普通问答可选择流式。页面保留部分文本并展示失败、截断和运行 ID；完整记录可在保存会话中分页恢复。模型默认最多取最近 30 轮成功上下文，还受字符、token 和缓存预算约束。
3. 自主 Agent 和索引操作建立后台任务。任务列表每 2 秒刷新，支持翻页、停止后续执行和从安全检查点继续。提交超时先用原操作标识检查或重试，同一逻辑请求不会创建第二个任务。没有安全边界或达到恢复次数上限时不能继续。
4. 在回答下选择证据范围并回读原文。范围是索引片段内的 Unicode 字符位置。版本、可见文本 hash 及提供的完整 chunk hash 不匹配时拒绝替换旧引用；长范围分段核验、分段展示。候选、模型可见材料和回答引用分别显示；这些标识不证明事实蕴含或“最新有效结论”。
5. 在草稿审批处核对收件人、正文、hash 与状态。批准只执行模拟动作或创建 Gmail draft。未知执行结果须人工核对并结案，不能自动重发。任务约束来源于具体用户轮次，不能代替审批授权。

## 查询与恢复契约

`/chat/sessions?limit=50&offset=0` 和 `/jobs?limit=10&offset=0` 返回 `next_offset`。`/chat/history` 使用 `after` 与 `next_after/has_more`，保留失败/部分完成记录，但它们不会被伪装成成功历史。列表按更新时间排序，活动中的记录可能移动；这些列表不是事务快照。

`/chat/history/search` 回查旧轮次，`/chat/history/summary` 返回带轮次的确定性摘录。`/chat/facts` 写入要求 `source_turn_id` 与 `expected_version`，防止覆盖已更新的约束。历史助手陈述只是会话资料，需要通过原邮件证据重新核对。

`/evidence/email` 支持 email/chunk、start/limit 与可选版本约束；`/evidence/reread` 接收已保存的引用；`/evidence/thread` 只列当前索引线程的日期和回复关系材料。单次正文预览不超过 4,000 字符，引用复核默认不超过 60,000 字符。底层仍重建单封邮件的 chunks，没有引入新的通用 EmailStore。

Agent `search_emails` 返回有界候选快照的 `items/next_cursor/coverage`，不是全邮箱枚举。游标绑定 owner、查询、过滤和索引代，进程重启或缓存淘汰后失效。`email_stats` 可对明确过滤条件/邮件集合做确定性统计；自然语言语义集合、未回复状态和附件正文不能冒充已覆盖。附件列表会保留未读/未知状态。

HTTP 429 表示本地执行槽已满，409 表示会话、版本、检查点或审批状态冲突，413 表示输入/模型预算不足。对具有副作用的逻辑请求，恢复前始终检查原任务与审批状态；新增操作应有新的明确意图和操作标识。

## 索引与兼容迁移

API/CLI 先对完整输入做有界流式预检，后构建独立 Chroma generation。只有完整校验通过才原子切换 active pointer；失败不会清空旧代。配置、清洗/分块源码、模型 revision、维度或规范化方式不兼容时会要求显式重建。不要手工把旧 manifest 改成“兼容”。

`python scripts/index_emails.py --list-generations` 查看保留代，`--resume-generation <id>` 继续已持久化的索引输入，`--rollback <id>` 校验并切回兼容代。`--clear` 表示用完整新语料替换当前索引，需先备份。同步 CLI 在完整范围核对后以替换代传播删除；历史原件、旧代和备份仍按留存策略处理。

Agent 工具 schema 和评测契约已经升级。旧 Agent 检查点不匹配时明确拒绝恢复；旧评测报告不可当作当前质量基线。恢复备份会隔离旧审批并禁用任务检查点，见状态恢复指南。

## 已验证和待验证

离线回归使用合成邮件、替身模型、真实临时 SQLite/Chroma、真实 Gmail SDK 的内存 HTTP transport 与实际 Streamlit 测试脚本，阻断模型/邮箱网络并隔离业务存储。测试覆盖机制和负例；不能据此声称当前真实邮件的答案质量、延迟、容量或授权已经验收。

真实黄金集、完整 105 题模型基线、冷/热首答、RSS/GPU 容量、24 小时运行、目标 Docker/CI 与备份 RPO/RTO仍要在配置就绪后执行。用 `scripts/benchmark_service.py` 和默认仅生成计划的 `scripts/ablation_matrix.py` 保存测量；未执行的成绩应明确保持 unavailable。原件/旧索引自动物理清理、附件解析/OCR、真实发送、第二邮箱、多用户和多 worker没有启用。

本轮离线测试环境并非已配置好的业务部署。请以 `scripts/doctor.py` 的实际诊断、`/ready` 以及目标模型/邮箱验收结果判断能否投入日常使用；依赖快照和索引 manifest不构成零故障承诺。
