# Service and RAG experiments

The HTTP harness calls only `/query` or the legacy RAG `/chat/stream`; it does not call Agent jobs or approval endpoints. A live invocation is explicit and can consume model quota. Use a separately started service with synthetic corpus/index and isolated session/approval/job/log paths. SSE creates session history, so a business service is unsuitable for load tests.

```text
python scripts/benchmark_service.py --url http://127.0.0.1:8000 --run-root <scratch> --endpoint query --attempts 100 --concurrency 1
python scripts/benchmark_service.py --url http://127.0.0.1:8000 --run-root <scratch> --endpoint stream --attempts 100 --concurrency 4
```

Use `--token-env <variable-name>` for an explicitly selected auth token; it is never included in output. Supply only a synthetic `--query`. Every invocation creates a unique run directory containing configuration, per-attempt scalar records and summary; prompts, answers and response error bodies are omitted. Failed HTTP status, malformed output, incomplete metadata and incomplete SSE streams remain in the attempt denominator. TTFT starts before the request and ends on the first nonempty token, excluding metadata-only events. Quantiles cover successful subsequent requests using a bounded 10,000-item reservoir and explicitly exclude the first request. Optional `--rss-pid <server PID>` samples that local process's RSS (requires installed psutil); missing sampling is unavailable and sampled max is not an exact peak.

To measure process-cold behavior, stop and restart the isolated service with warmup disabled, verify its new PID, then run once with `--cold-process-first`. The flag is your attestation of that setup, not automatic proof of model/cache state. Without it the first request is labeled `first_observed`. Subsequent requests are not guaranteed cache hits. Compare separate runs at concurrency 1/2/4 and several synthetic query sizes, keeping corpus/index/model/config revisions fixed. The first request is serialized before concurrency workers so it is clearly separated. HTTP idle-read timeouts and deadline checks bound work as far as client APIs permit; scheduling/blocking reads can overshoot. This script cannot measure model loading before server startup or promise an absolute cancellation deadline.

For a 24-hour soak, first pass short offline and isolated smoke tests, record service PID/config/corpus/index hashes and disk space, then use `--attempts 0 --duration-seconds 86400 --concurrency 2 --timeout 60 --rss-pid <PID>`. Watch disk growth and service logs outside the benchmark. On completion retain config, attempt records and summary, compare failure rates and RSS over time, and reconcile any interruptions. Duration stops admission of new requests; already running requests may finish after it. No 24-hour soak or live model run is claimed by the repository's synthetic tests.

`python scripts/ablation_matrix.py --run-root <scratch>` creates V1–V7 plans from the existing evaluator's canonical flags without importing settings/models or invoking a provider. Every cell preserves exact flags, evaluator/dataset hashes and explicit unavailable scores. `--execute` deliberately runs one fresh subprocess per version through `run_ragas_eval.py`, with `--version-timeout` and isolated output/state paths. It reads your configured corpus/index/model settings during that explicit execution. Review each report's scoring method: embedding proxy degradation is not equivalent to LLM scoring. Heavy models, real quality results and equal live model snapshots remain pending actual controlled execution.
