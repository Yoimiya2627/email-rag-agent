# 当前版本小规模效果评测

本轮使用 **12 封固定合成邮件、12 道固定题目，每个代码版本的每题运行一次**。实际调用当前工作区代码的 `/query` HTTP 接口、缓存中的 bge-m3 和远端生成模型，没有替换模型响应，也没有把标准答案放入请求。12 题自动检查全部通过；主 agent 逐题对照原始邮件审阅，未发现回答事实或引用支持关系错误。

这是小样本功能验收，不代表真实邮箱准确率、全面抗提示注入能力、105 题 Agent gate 成绩或并发容量。题目包含清晰的项目名称，多数是短邮件事实查询；不能将这里的 100% 外推到复杂长邮件。

## 数据、配置与版本

- [合成邮件](../../../data/portfolio_demo/emails.json)：12 封、12 个索引片段，地址全部使用 `example.invalid`。包含预算初稿与正式版本、会议、发票、发布门槛、英文交付、未解析附件和干扰邮件。
- [固定题目及规则](../../../data/portfolio_demo/cases.json)：10 道事实/比较题、2 道信息不足题。标准答案只用于本地评分，不提供给生成模型。
- 路径：`/query`，`top_k=5`；bge-m3 + BM25 + RRF，reranker / query rewrite 关闭。自然语言过滤抽取仍会调用模型。
- 生成模型配置：`deepseek-v4-flash`；嵌入模型 `BAAI/bge-m3`，revision 为 `5617a9f61b028005a4858fdac845db406aefb181`。这是配置标识，不能证明远端服务内部权重永久不变。
- [环境记录](environment.json)、[源码及数据指纹](source-manifest.json)、[完整逐题响应](evaluation-results.json)。指纹以当前工作区文件内容为准，包含未提交修改；运行前后所记录的源码指纹一致。

## 实测结果

| 指标 | 本轮结果 | 口径 |
|---|---:|---|
| 预设任务检查通过 | 12 / 12 | HTTP 成功、生成完成、必需事实匹配、禁止事实未出现、gold 邮件检索与引用齐全、引用 ID 有效，全部满足才算通过 |
| Gold 邮件平均召回率 @5 | 100% | 每题所需邮件与返回候选邮件的集合交集比例，再对 12 题平均；按邮件计，不是 chunk recall 或检索 precision |
| 引用 ID 有效率 | 14 / 14 | 答案中的 `email_id#chunk_id` 必须对应实际返回的来源；同一引用重复出现按次数计 |
| 主 agent 逐题语义审阅 | 12 / 12 | 对照完整合成邮件，检查金额、时间、对象、版本选择、比较结果及信息不足表述；交叉审核单独记录 |
| 平均请求耗时 | 1.845 秒 | 模型预热后，客户端发出完整 HTTP 请求至收到响应，包括过滤、检索和生成，不含浏览器渲染 |
| p95 请求耗时 | 2.859 秒 | nearest-rank；12 题时等于本轮最大值，仅反映这个小样本 |
| Provider token 总量 | 15,413 | 汇总这 12 个请求的实际 usage，缺失 usage 调用为 0；不含另外录制的演示 |
| 建索引耗时 | 16.796 秒 | 包含首次本地模型加载 12.754 秒、嵌入 3.900 秒；不计入问答耗时 |

未配置用于核算的单价，因此不报告金额，也不把 usage 中的占位成本 `0.0` 解释为免费。没有测量首 token 延迟或并发吞吐。

## 复现

在项目已安装依赖、配置模型 API key、准备好嵌入模型缓存后执行：

```powershell
.\.venv\Scripts\python.exe scripts/run_portfolio_eval.py --run-dir E:/email-agent-validation/my-evaluation
```

运行目录必须是新的、位于仓库外的完整 ASCII 路径。脚本忽略日常应用配置，只继承明确允许的模型连接和缓存设置；邮箱账号、会话、审批和索引全部写入新目录，provider 固定为 simulated，邮箱定时同步关闭。

输出 `results.json`、`source-manifest.json`、`environment.json` 和 `cleanup.json`。异常和失败保留在分母，不自动重试覆盖首次答案；usage 缺失时总 token 报告为未知。不同机器、模型服务版本和再次运行可能产生不同答案及耗时。

首次评测为 12/12 通过。随后浏览器演示发现并修复了来源回读按钮问题，因此在最终代码上完整重跑相同的 12 题，上表使用这次结果；没有改变题目、gold 或评分规则。首次结果另存为 [修复前原始评测](evaluation-before-ui-fix.json)，不会用修复后的响应覆盖它。索引耗时受本机模型/系统缓存影响，两次时长差异不能归因为这个界面修复。旧 V1–V7 评测没有重跑，见 [历史评测说明](../../evaluation.md)。
