## 兼容性与发布说明

1. **旧 checkpoint 需要重启任务**：缺少可靠 `reference_clock` 的 v1/v2 checkpoint 明确返回 `checkpoint_reference_requires_restart`。不会从历史提示文本推测时间，也不会套用当前时间续跑。升级后先核对已完成步骤和审批状态，再新建任务；已保存证据保留，避免盲目重复操作。
2. **MCP 客户端与服务器配套升级**：冻结时间的 Agent 要求服务器支持 `email-agent/reference-clock` 元数据协议 v1，并核对服务器实际应用时间的回显。旧服务器在模型执行前明确拒绝。未冻结的传统直接 MCP 调用保留实时语义。
3. **评测输出不可覆盖**：已有结果文件或 sidecar 锁时直接拒绝；每次运行选择新路径，崩溃遗留锁不自动抢占。该协议保护遵守协议的评测进程，不宣称可以阻止任意外部程序改写磁盘。

实现与回归边界见[参考时间修复说明](reference-clock-repair.md)。新逻辑任务冻结时间、恢复原任务时间、检查可信作用域冲突分别验证；调度、审批有效期与运行超时仍使用真实时间或 monotonic 时钟。

使用独立分支 `codex/integrate-evaluation-20261102` 发布修复与证据，保留既有远端提交的祖先关系；不改写远端历史，不直接合入 main。原旧基线工作区继续保持原状。

## 复核与复现

先准备与记录相符的独立输入/索引副本、依赖和本地模型缓存，并配置调用凭据；输出必须是不存在的新路径。实际本次使用了单独启动器将可写状态重定向至隔离目录，仅在子进程加载既有凭据，没有把环境文件复制进仓库。

```powershell
python -X utf8 -B scripts/paired_acceptance.py --root . --gold '<独立 gold 副本>' --reference-time '2026-11-02T12:00:00+08:00' --case-timeout 180 --output '<不存在的新结果路径>'
```

上述命令应在 `EMAIL_DATA_PATH`、`CHROMA_PERSIST_DIR` 及状态路径已经指向独立副本的环境执行。完整 5040 封索引快照仍在本地，不随公开证据上传；仅 clone 仓库不能据此保证得到同一快照或精确分数。重建索引或换数据时，应记录新条件和实测结果，不能沿用本次成绩。原文件 LF/CRLF 字节也可能影响旧索引兼容性指纹，不应绕过检查。
