## 运行与恢复契约

一个逻辑 Agent 任务只确定一次检索参考时间。planner、过滤抽取、本地检索、后续工具和收尾回答共享它；运行结束或抛出异常时恢复调用方上下文。调度器、审批有效期和运行超时继续使用真实时间或 monotonic 时钟。

`core/run_reference.py` 复用 `core/pipeline.py` 已有 ContextVar，没有建立第二份时钟状态。新 checkpoint 保留外层 v1/v2 结构，新增独立的时间子契约：

```json
{
  "reference_clock": {
    "version": 1,
    "instant_utc": "2026-04-28T15:59:59+00:00",
    "timezone": {"kind": "offset", "microseconds": 28800000000}
  }
}
```

IANA 时区保存名称；固定偏移保存精确整微秒。参考瞬间规范化为 UTC 后参与 `context_fingerprint`，时区策略单独绑定。同一瞬间的不同 offset 表示兼容；不同瞬间、不同日期解释策略不兼容。

恢复顺序是：本地校验安全标志、结构版本、身份与持久引用、任务 guard、时间字段及可信作用域冲突，使用规范化的原任务时间校验 fingerprint；随后读取 backend schema 并校验，确认远端时钟能力；全部通过后进入冻结作用域，恢复消息与执行状态，最后才创建模型客户端并继续执行。读取远端 schema 是控制面请求，不执行业务工具。可在本地判定的旧／无效／冲突 checkpoint 在读取 backend schema 前拒绝。

旧 v1/v2 checkpoint 缺少可靠时间字段时，返回 `checkpoint_reference_requires_restart`，不从提示文本猜测日期、不默默套用当前时间。后台任务保留原 checkpoint 和已完成证据，并阻止在该错误后反复恢复；API 和前端提示用户核对已完成步骤、审批状态后创建新任务。其他时间错误只暴露白名单错误码，不输出任意异常正文。

## MCP 远端边界

本地 ContextVar 不会跨进程传播。新客户端通过 MCP transport metadata 的 `email-agent/reference-clock` 字段传递时间子契约；该字段不出现在模型可填写的工具参数 schema 中。

新服务器在工具 metadata 中声明协议版本 1，校验请求契约后冻结业务工具的检索时间，并回显实际应用的规范化契约；客户端核对回显。owner、审批和超时不从这份元数据取得。冻结 Agent 使用不支持该协议的旧服务器时，在模型调用前明确拒绝，要求同步升级服务器或使用本地工具。未冻结的传统直接 MCP 调用保留实时语义。

远端操作已提交但回显丢失／不匹配时，需审批操作仍按“结果未知”处理；保留同任务重复请求的缓存保护和安全审计，避免因新错误分支再次提交操作。

## 评测输出所有权

`scripts/eval_output.py` 为 paired、recall 和 gold 模板入口提供同一写入协议：

- 在模型、索引和运行元数据初始化前独占创建 sidecar 锁及目标 JSON；已有目标或锁立即拒绝，不提供覆盖开关。
- 整个运行持有所有权，只有持有者可以通过临时文件和原子替换更新 checkpoint；写入前验证目标身份、内容摘要及锁身份。
- 发现外部修改后停止写入，异常回写也不覆盖外来证据。
- 普通失败、provider 中断和取消保留已完成记录；未完成结果不发布 aggregate。最终写入失败时，能写回则保存 aborted partial，持续失败则保留上一次有效 JSON，并返回非零退出码。
- 崩溃遗留锁不自动抢占。重试应选择新输出路径；不要把旧结果当作可覆盖的临时文件。

独占协议严格保护采用该协议的评测进程；文件身份与摘要检查不等同于阻止任何外部程序写磁盘的操作系统强制锁，不能保证非合作程序在最后检查与替换之间写入也不被覆盖。
