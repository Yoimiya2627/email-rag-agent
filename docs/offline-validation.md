# Offline validation and evaluation evidence

Run deterministic checks with `python scripts/offline_tests.py tests/ -q`. This wrapper runs pytest in a guarded child process: it disables dotenv loading and network connections, puts state outside the checkout, and rejects writes into source files. The parent waits for process exit before cleaning the validated temporary directory, so SDK-owned SQLite/Chroma handles cannot mask the actual test exit code; cleanup failures remain explicit. CI exercises Windows/Python 3.10 and Ubuntu/Python 3.11, with a separate Chroma storage profile. A workflow definition is not proof that those hosted jobs have passed.

`python scripts/doctor.py --profile core` inspects configuration shape and installed package versions without model loading, downloads, OAuth or provider requests. A successful diagnosis does not establish model, index or Gmail readiness. Token-file presence does not establish a valid grant. Never paste token contents into diagnostic reports.

Installed versions are captured by `scripts/lock_test_dependencies.py --profile test|storage|application --output <file>`. The constraints files contain the installed dependency closure of named project roots, excluding unrelated packages. Use `pip install -r requirements-test.txt -c requirements-test-constraints.txt` for core tests, or `pip install -r requirements-test-storage.txt` for storage. Application constraints cover installed UI/Gmail libraries as well; heavyweight embedding/reranking model packages and downloaded model revisions still require a separately tested deployment environment. These are version snapshots without wheel hashes, not a universal cross-platform or complete production lock. Run `pip check` after installing. No automatic installation occurs during diagnosis or tests.

Run `python scripts/offline_benchmark.py --work-dir <scratch-dir> --output <report.json> --sizes 10,100 --lengths 256,2048 --workers 1,2` for an eight-cell synthetic SQLite experiment. Each cell runs in a fresh Python subprocess, creates a temporary approval database and never approves anything. Reports distinguish process startup, first create, warm create quantiles, attempts, failures, listing time and Python allocation peak. This measures the approval store only: it does not establish RAG capacity, model cold/warm latency, RSS, TTFT, retrieval recall or answer quality. Preserve failed attempts in denominators. `measure_latency.py` likewise reports attempted/succeeded/failed and labels quantiles as successful-only.

Live evaluation is explicit: `python scripts/run_agent_eval.py` uses the configured model, corpus and index. Every run gets a unique run directory, eval owner, approval store and trace/audit paths. Simulated approvals are isolated too. Remote MCP evaluation is refused because this process cannot guarantee isolation of remote server state. Never use a daily approval store as an evaluation override. The current runner uses `data/agent_testset.json`; the hard-case JSON in this directory is a synthetic template pack, not an executed quality report or an alternative CLI dataset.

Canonical dataset IDs bind task text, task type, risk, success criteria, expected tools, forbidden tools and optional `tool_assertions`. An assertion specifies `tool`, one-based `occurrence`, `source` (`arguments` or normalized `result`), dot-separated `path`, and JSON `equals`. In-memory observation stores only value/spec hashes; a wrong sender, ID, status, missing occurrence or missing proof fails the deterministic contract. Hashes prevent accidental mismatch, not malicious report fabrication or recovery of low-entropy private fields. Reports remain trusted local evidence and cannot certify an untrusted report author. Judge score requires exact integer 0/1, complete output, no automatic retries, a configured time budget and a context budget. Judge failures are distinct from task failures.

Provenance records source/dataset hashes, contract version, safe effective configuration, installed versions, corpus hash and validated active index manifest. Unknown model snapshots are explicitly unavailable; a model alias is not a reproducible checkpoint. The existing historical report predates these contracts and must not be relabeled as current. Strict gate validation is required when dataset/report files change or when manually dispatched. Source-only PRs surface stale evidence as an informational freshness check; deterministic tests remain required, and that informational check does not approve model quality.

MCP server audit contains boundary, request ID, hashed configured owner, tool/resource kind, status and elapsed time. It omits arguments, mail IDs/bodies and bearer tokens. It is operational evidence, not a tamper-proof or complete compliance log.

Agent evaluation pins one immutable index generation for the entire batch and reads provenance from that same pinned descriptor. Activating a new generation during the batch does not mix it into later cases. Missing manifests are explicitly marked unavailable_no_immutable_generation, not certified as a fixed legacy collection.
