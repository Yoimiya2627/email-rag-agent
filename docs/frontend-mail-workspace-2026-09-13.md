# 邮件助手界面（2026-09-13）

界面按用户选择，以聊天为首页。左侧只显示助手对话、查看邮件和邮箱设置三个入口；不再把邮件列表、正文、对话及后台任务挤在同一页。品牌使用直白的「邮件助手」，保留小型邮票标记。

## 页面分工

| 入口 | 用途 | 数据范围 |
| --- | --- | --- |
| 助手对话 | 大对话区，底部固定输入框；新建或恢复会话 | 自由对话和单独导入的资料，尚未接入真实邮箱 |
| 查看邮件 | 浏览、搜索、阅读；立即同步 | 当前账号在本地同步的邮件 |
| 邮箱设置 | 账号授权、同步范围和间隔、解析报告 | 当前账号设置；后台任务和高级工具默认收起 |

聊天首页不查询或展示全局任务列表。运行中的 Agent 任务仅显示当前会话的简短状态，完成后把答案一次性加入对话。失败、停止、无答案及服务不可用有明确提示；不会自动重试或恢复。请求超时后的显式查询或重试继续使用原操作标识，并把结果绑定到原会话。

「对话设置」保留模式、流式输出和保存会话功能；「高级工具」保留原有索引管理、审批、证据、历史约束及全局任务管理能力。切换页面不会把当前邮件加入模型请求。

对于「你现在可以看到我163的邮件吗」这类完整的邮箱访问能力询问，界面直接读取当前账号的本地汇总状态，明确区分已同步邮件与尚未接通的AI问答。状态不可用时不会编造数量，且不读取正文或调用模型。这类「本机状态说明」属于当前浏览器会话中的临时状态提示，不写入服务端模型对话记录；具体邮件任务仍走原有处理流程。输入第一条消息后立即收起欢迎区，普通聊天隐藏任务编号及上下文诊断；高级工具仍可查看。

邮件页面初次进入只显示列表，由用户选择一封阅读；切换页面仍保留已选择的邮件。列表主题限制为两行，完整主题显示在阅读区。不同账号保留各自的搜索和页码。

## 正文显示修复

真实 MIME 解析记录保留表格位置和单元格信息，但不保留冗余的行 text 字段。旧显示代码依赖该字段核对，因此真实表格回退成了内部标记。

现在仅在完整元数据重建出的规范行与正文位置精确一致时，显示可读的单元格。规范空表显示「表格未提取到可显示内容」。无法核对的片段保留转义原文；用户自写的标记不会被正则删除。没有改动原始邮件、数据库或索引。

## 视觉与验证

沿用深海色导航（#173238）、白色对话区（#FFFFFF）、浅灰背景（#F1F5F6）、青绿色操作（#0F766E）和灰蓝文字（#657780）。使用本机字体，没有新增远程图片或字体依赖。

- 完整离线回归：1418项通过、190项子测试通过，144.51秒；2项因当前Windows账户的符号链接权限而跳过。
- 邮箱能力询问、聊天、会话任务和上下文界面定向复验71项通过；实际浏览器验证同一句能力询问得到本机状态说明，欢迎区收起且无任务编号。
- 合成测试覆盖当前任务的去重交付、跨会话隔离、显式停止、临时断网、失败与无答案，以及真实HTML→MIME链路下的表格显示。
- 只读核对本地39封邮件：37封原有内部表格标记，修复后显示层残留0封。只输出数量，没有上传真实邮件或调用模型。
- 独立Chrome测试实例连接正在运行的127.0.0.1:8501，验证1440×1000与390×844布局：无横向溢出，输入框在可视区域内，没有全局任务列表；邮件在点击后打开，搜索和清除正常。
- 截图在捕获前遮盖私人内容。测试未控制用户已有Chrome资料，未向模型提交真实邮件。

## 使用与边界

在外部浏览器刷新，点击左侧「助手对话」即可使用新布局；已有浏览器会话保留当前所在页面。后端无需重启，没有改变自动同步计划。

真实邮件仍仅做本地收取、解析和搜索，AI问答权限没有扩大。当前支持163连接，QQ连接、发送和删除能力不因界面调整而启用。本轮没有新增安装，临时测试与截图位于E盘。
